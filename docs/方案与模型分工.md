# 方案与模型分工

## 三层分工

| 层次 | 解决的问题 | 保留的证据 |
|---|---|---|
| ASR | 说了什么 | 原始片段、时间、识别参数与运行记录 |
| 说话人分离 | 哪些时间区间属于哪个匿名声音簇 | 原始分离区间、重叠证据与标签限制 |
| 文本分析 | 文字中的主题、决定、行动与待确认项 | 来源时间范围、引用证据、推断和建议的区别 |

说话人标签只在当前文件或明确连续的联合输入内有效。标签不等于真实姓名，也不能跨设备直接对应。

## 四种计算方案

| 方案 | 组合 | 适用条件 | 主要代价与边界 |
|---|---|---|---|
| 默认完整流程 | 全文件 large-v3 + 全文件 Sortformer + 完整文字审阅 | 需要可追溯全文与报告 | 包含 GPU、传输、审阅和 PDF 验收开销 |
| 快速初读 | 本地 MLX Whisper turbo，或 CPU/int8 Whisper；先输出文字与粗分类 | 需要先判断内容是否值得深入处理 | 快速版不等于最终版；缺少分离时明确标注 |
| 自适应复核 | 默认基线 + 疑难区间第二识别模型，必要时第三模型 | 长录音中只有部分区间不可靠 | 降低重复计算，但应检查窗口边界及遗漏 |
| 完整多模型 | 全文件 Whisper + Qwen3-ASR + VibeVoice-ASR，逐区间保存候选并仲裁 | 用户明确要求模型比较或全文交叉核验 | 计算与人工核对显著增加；多模型一致仍可能共同出错 |

快速流程可以缩减交付范围，但应按用户目标决定；不要把短摘要写成完整逐字稿。已有可信转写时，优先复用并补报告；当问题是识别缺漏、定位错误或声音归属时，再升级相应的音频步骤。

## 音频模型

- **faster-whisper / large-v3**：作为历史默认文字基线。采用 CUDA FP16、VAD 和关闭长录音跨段前文条件的配置；这些是复现配置，不是适用于所有音频的最佳参数。[上游文档](https://github.com/SYSTRAN/faster-whisper)
- **本地 MLX Whisper / turbo**：历史快速初读路线，适合已有 Apple Silicon 环境；量化、模型大小和设备会改变质量与速度。CPU 路线使用独立实现，不把 MLX 与 CPU/int8 当作同一后端。[MLX 实现](https://github.com/ml-explore/mlx-examples/tree/main/whisper)
- **Qwen3-ASR-1.7B + ForcedAligner**：第二文字候选与独立文本—音频定位。强制对齐把给定文字放到音频时间线上，并不证明这段文字本身正确。[上游文档](https://github.com/QwenLM/Qwen3-ASR)
- **VibeVoice-ASR**：结构化文字、时间和说话人候选，用于另一种视角的复核。即使模型提供说话人字段，也要核对身份漂移、截断和时间覆盖。[上游文档](https://github.com/microsoft/VibeVoice)
- **NVIDIA Sortformer 4spk v2.1**：历史默认独立分离器，最多 4 个匿名声音身份；更多参与者可能合并。[模型卡](https://huggingface.co/nvidia/diar_streaming_sortformer_4spk-v2.1)
- **pyannote Community-1**：历史对照分离路线，保持独立结果，不与 Sortformer 标签直接拼接；选用时按目标环境准备依赖与模型授权。[模型卡](https://huggingface.co/pyannote/speaker-diarization-community-1)

这里记录已有流程的模型角色，不声称这些版本是当前最新或所有场景最优。

## 文本模型与推理强度

历史运行环境使用过 `gpt-6-sol` 的 medium/high，以及 `gpt-6-astra` 的 medium/high 配置。它们是运行记录中的配置名，接收方应核对自己的平台是否支持这些 ID 和推理选项。

| 工作 | 起始路由策略 | 升级条件 |
|---|---|---|
| 已定义分类表的标签、短材料复核 | 日常模型 + medium | 标签边界模糊、跨段冲突或证据不足 |
| 单份完整报告 | 日常模型 + high | 复杂推断、多来源差异或高影响结论需要复查 |
| 跨来源比较、矛盾分析、困难仲裁 | 更强模型 + medium/high | 独立审阅发现具体缺陷，再扩大复核范围 |

这些是可配置工作策略，尚无受控实验能证明某一组合稳定胜出。不要依据推理强度名称估算固定 token 倍率，也不要从付费层级推断识别准确率。

model 与 reasoning.effort 属于运行配置；skill 主要提供可复用指令和资源，不能保证覆盖当前工具或会话的模型设置。[OpenAI 配置文档](https://developers.openai.com/api/docs/guides/agents-api/configuration) [OpenAI reasoning 文档](https://developers.openai.com/api/docs/guides/reasoning)
