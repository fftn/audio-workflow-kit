# 可追溯音频转写

接收用户指定的文件或目录。冻结来源清单，检查可完整解码时长、编码、声道、采样率、大小及哈希。保留原件，分析使用副本。

默认完整方案采用 faster-whisper large-v3 和 NVIDIA Sortformer 4spk v2.1。接收方没有 GPU 或明确要求快速版时，按现有设备配置识别路线，并记录缩减的环节与质量限制。[参数与执行](references/execution.md)

先确认接收方运行设备与依赖；本 skill 不内置服务器地址。已指定本地／自托管位置时遵循该位置，信息缺失且影响数据去向时询问。文本报告是否调用外部模型也是独立的数据处理选择。

## 处理

1. 识别完整来源，输出 raw JSON/TXT/SRT。保持原始文字，不用个人词表自动猜测专名。采用简体中文校订层时保留原始层。
2. 对需要声音归属的来源做完整音频分离。保持模型原始区间，独立写结果，不将标签当作姓名。
3. 以累计时间重叠对齐 ASR 片段与声音簇，记录各簇重叠量。没有可靠证据时保持未知；可能同时发言时保留标记。
4. 检查完整性、输出上限、时间越界、零时长、重复句和长静音稀疏识别。空文字不能直接判定无讲话。
5. 阅读全文及转场，只有高置信修正才进入校订层。时间不可靠的片段不用于准确归责。
6. 根据用户目标交付全文、索引、报告、PDF和可用音频副本。生成 PDF 时逐页渲染与查看；不要把自动文本检查当作视觉验收。

明确连续的多个文件才按原顺序构造统一时间轴，并保留每份来源偏移。其他来源保持分开。Sortformer 本版本最多 4 个声音身份，超出容量或未知身份时不能强行分配责任人。

若使用远端推理，建立任务独立目录，仅在该目录放音频、结果和任务日志。下载校验后删除精确任务目录并检查不存在；不要删除接收方其他任务或模型缓存。

## 完成条件

原件哈希未变；所有预期来源有完整交付或明确失败／不足记录；模型及计时配置可追溯；原始、校订、报告层区别清楚；内容、时间和声音风险已标记；需要清理的远端任务已证实不存在；最终文件校验通过。
